# Product

## Platform

web

## Users

主要用户是两类，场景与使用频率完全不同，这决定了界面不能用一套语言：

1. **后台管理员**（HR / 工会 / 评议组织者）：一年组织几次评议，但在评议期间每天多次进入后台。要做的事是配置打分表结构（部门、职工、项点）、按占比发放随机码、监控发码与提交进度、控制开放时间窗、结束后导出结果与打印归档。坐在办公桌前用电脑，需要高密度信息与键盘效率。
2. **普通职工**（投票人）：一年参与一到两次，凭一张随机码进入。要做的事是输入码、选部门、在一张类 Excel 表单上逐格打分、提交。可能用办公电脑，也可能用手机；不熟悉系统，只做一次，不能出错，也看不懂后台术语。

## Product Purpose

把线下的职工素质评议搬到线上，并保证结果可信：职工匿名打分，后台按票种权重算出可上报的成绩，同时留下可打印归档的正式打分表。

成功意味着：评议按期完成、参与进度可追踪、成绩可复现、职工相信它是匿名的。

## Positioning

同类投票工具通常只做「投票」，不做「结构化打分表」。本系统的机制是：**打分表的行列由后台按部门配置**（行 = 该部门职工，列 = 素质项点，每项 min/max 单独设置），配合票种权重对各票种加权求和，缺少某票种时按实际有票的票种归一化。这把「评议表长什么样」变成可配置数据，而不是写死的表单。

## Operating Context

- 评议是**周期性、有截止时间**的活动。开放时间窗之外，系统必须拒绝进入与提交，而不只是隐藏入口。
- 随机码是**线下发放**的：会被打印、剪裁、逐张发给职工，因此码要短、不含易混字符（无 O/0/I/1），并且能导出成表。
- 结果要**上报与归档**：需要 Excel 导出，以及一份含签字栏的可打印正式打分表。
- 部署在单位内网的 Linux 服务器（Node + Nginx + PostgreSQL），日常使用者不承担运维复杂度。

## Capabilities and Constraints

**已确认能力**：部门 / 职工 / 项点配置、票种与权重、批量发码与作废、码状态查询与导出、投票开放时间窗、匿名打分表（类 Excel 网格）、票种加权与归一化计分、排名、Excel 导出、打印版打分表、管理动作审计留痕、职工名单 Excel/CSV 导入。

**硬约束**：

- 一码一票，提交即核销，不可修改；并发安全靠数据库原子更新，不靠前端拦截。
- 分数**只能是整数**，且必须落在该项 min/max 区间内。
- 一个随机码只能评一个部门。
- 匿名是物理隔断：评分表不含随机码、IP、User-Agent。代价是无法自动排除「给自己打分」。
- 启用票种的权重合计必须为 100%（前端「权重分配」表单强制；后端硬边界是不超过 100%，允许逐项调整时的中间状态，计分按实际权重合计归一化，中间态不影响正确性）。
- 单次发码上限 2000 张/票种。

**术语**：票种（A/B/C）、随机码、项点、部门、职工、打分表、综合得分、归一化。

**明确未定（不是遗漏）**：外部人事系统接口本期不对接（`employeeNo` 已作唯一标识预留）；生产库连接串由部署方填写；AES-128 加密能力已铺通但本期不落任何加密字段。

## Brand Commitments

- 系统名称取自 `system.title` 设置项，默认「职工素质评议」；打印版抬头同源。
- 无既有 logo、无 VI 手册、无指定字体。**不得虚构单位名称、徽标或口号。**
- 语气：正式但不生硬。面向职工的界面不得出现后台术语（「票种权重」「归一化」「批次」这类词不出现在投票端）。

## Evidence on Hand

- 可运行的全栈实现（Express 5 + React 19），161 项自动化测试全绿，含端到端链路与真实进程验证。
- 真实数据模型与 API 契约，因此界面可以接真实数据，不需要假接口。
- **不存在**：真实职工姓名、真实部门名、真实成绩、单位徽标、真实评议通知文案。演示数据必须标注为合成。

## Product Principles

1. **匿名不可妥协**：任何提高可追踪性的便利都不换取它；界面措辞也不能暗示系统知道是谁投的。
2. **职工作业零学习成本**：投票人只做一次，界面必须自解释；后台术语不出现在职工界面。
3. **管理员的效率优先**：后台是每天多次使用的工具，密度、键盘可达、可扫描性高于视觉表达。
4. **结果可复现、可解释**：计分口径要在界面上写明，不做黑箱；导出与页面数字必须一致。
5. **截止时间与核销是硬的**：开放窗口与一码一票由后端强制，前端提示只是提示。

## Accessibility & Inclusion

未获得书面的合规标准要求。以下为已确认的技术基线（不是猜测）：WCAG 2.1 AA 对比度（正文 4.5:1、大字 3:1）、完整键盘可达、可见焦点、尊重 `prefers-reduced-motion`、移动端触摸目标 ≥44px。

打分表需支持键盘连续录入，这既是效率要求，也顺带满足了键盘可达性。
